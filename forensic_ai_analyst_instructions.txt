AUDIT_RETURNS FIELD DEFINITIONS
==================================================

--------------------------------------------------
IDENTITY
--------------------------------------------------

ticker:
Ticker symbol.

date:
Trading date being reconciled.

--------------------------------------------------
PRICE / ADJUSTED CLOSE FIELDS
--------------------------------------------------

ms_close:
Massive unadjusted close.

yf_close:
yFinance unadjusted close.

ms_adj_factor:
Massive cumulative adjustment factor.

yf_adj_factor:
yFinance implied adjustment factor:
yf_adj_close / yf_close

ms_adj_close:
Massive adjusted close:
ms_close * ms_adj_factor

yf_adj_close:
yFinance adjusted close.

--------------------------------------------------
EVENT MARKER FIELDS
--------------------------------------------------

ms_div_split:
Massive event marker string.

yf_div_split:
yFinance event marker string.

Split format:
sp:<split_factor>

Example:
sp:1.136

Cash distribution format:
ca:<cash_amount>

Example:
ca:0.82

Multiple events may be semicolon-separated.

has_div_split_mismatch:
TRUE when Massive and yFinance event markers differ.

--------------------------------------------------
RETURN FIELDS
--------------------------------------------------

ms_return_price:
Massive raw price return from unadjusted closes.

yf_return_price:
yFinance raw price return from unadjusted closes.

ms_return_div_split_implied:
Massive implied event return:
ms_return - ms_return_price

ms_return_div_split_actual:
Massive explicit event return derived from Massive events.

yf_return_div_split_implied:
yFinance implied event return:
yf_return - yf_return_price

yf_return_div_split_actual:
yFinance explicit event return derived from yFinance events.

diff_ms_return_div_split:
Difference between Massive implied vs explicit event return.

diff_yf_return_div_split:
Difference between yFinance implied vs explicit event return.

ms_return:
Final Massive adjusted return.

yf_return:
Final yFinance adjusted return.

diff_return:
IMPORTANT SIGN CONVENTION:

diff_return = yf_return - ms_return

Therefore:
- positive diff_return => yFinance return is higher
- negative diff_return => yFinance return is lower

--------------------------------------------------

--------------------------------------------------

needs_review:
TRUE when review is required.

review_priority:
HIGH / MEDIUM / LOW review priority.

Massive heuristic anomaly score.

Deterministic diagnostic classification.

Important values include:
- CLOSE_REVERSAL
- MS_MISSING_EVENT_ADJUSTMENT
- MS_EVENT_DATE_MISMATCH
- MS_ADJ_FACTOR_CONTINUITY
- MS_DIV_SPLIT_RETURN_MISMATCH

massive_problem_summary:

massive_why_incorrect:

SPLIT RECONCILIATION RULE
==================================================

If:
- ms_div_split or yf_div_split contains sp:<split_factor>

Then:
expected_return_impact = split_factor - 1.0

Example:
sp:1.136 => expected_return_impact = +13.6%

Do NOT confuse:
- event return impact
with:
- backward price adjustment factor

For sp:1.136:
- event return impact = +13.6%
- backward price factor = 1 / 1.136
- backward price effect ≈ -11.97%

audit_returns() uses the EVENT RETURN convention.

When a split exists, compare:
- expected_return_impact
- diff_return
- ms_return_div_split_actual
- yf_return_div_split_actual
- implied event-return fields

If:
- yFinance has the split
- Massive does not
- yFinance event return explains diff_return

Then:
likely_correct_source should usually be YFINANCE.

If:
- Massive has the split
- yFinance does not
- Massive event return explains diff_return

Then:
likely_correct_source should usually be MASSIVE.
