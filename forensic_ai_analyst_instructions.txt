AUDIT_RETURNS FIELD DEFINITIONS

--------------------------------------------------
IDENTITY
--------------------------------------------------

ticker:
Ticker symbol.

--------------------------------------------------
PRICE / ADJUSTED CLOSE FIELDS
--------------------------------------------------

source1_close:
source1 unadjusted close.

source2_close:
source2 unadjusted close.

source1_adj_factor:
source1 cumulative adjustment factor.

source2_adj_factor:
source2 implied adjustment factor:
source2_adj_close / source2_close

source1_adj_close:
source1 adjusted close:
source1_close * source1_adj_factor

source2_adj_close:
source2 adjusted close.

--------------------------------------------------
EVENT MARKER FIELDS
--------------------------------------------------

source1_div_split:
source1 event marker string.

source2_div_split:
source2 event marker string.

Split format:
sp:<split_factor>

Example:
sp:1.136

Cash distribution format:
ca:<cash_amount>

Example:
ca:0.82

source1 cash marker formats:
cd:<cash_amount> = source1 regular cash dividend.
sc:<cash_amount> = source1 special cash dividend.
ca:<cash_amount> = generic cash action/distribution marker when no regular/special distinction is available.

source2 cash marker format:
ca:<cash_amount> = source2 generic cash dividend/distribution marker.

For economic event matching, cd:<amount>, sc:<amount>, and ca:<amount> are all cash distribution markers. Do not treat cd/sc versus ca as an event-source mismatch by itself when the cash amount and date reconcile.

However, sc:<amount> is research-relevant. Special cash dividends more often create data source adjustment, denominator, event classification, or timing differences than ordinary regular dividends. When source1_div_split contains sc:<amount>, explicitly investigate whether the special dividend caused the return difference or adjustment treatment.

Multiple same-day events are space-separated.

has_div_split_mismatch:
true when source1 and source2 event markers differ.

--------------------------------------------------
RETURN FIELDS
--------------------------------------------------

source1_return_price:
source1 raw price return from unadjusted closes.

source2_return_price:
source2 raw price return from unadjusted closes.

source1_div_split_factor_implied:
source1 implied dividend/split factor inferred from adjusted and raw price returns:
(1 + source1_return) / (1 + source1_return_price)

source1_div_split_factor_explicit:
source1 explicit dividend/split factor derived from source1 event records.

source2_div_split_factor_implied:
source2 implied dividend/split factor inferred from adjusted and raw price returns:
(1 + source2_return) / (1 + source2_return_price)

source2_div_split_factor_explicit:
source2 explicit dividend/split factor derived from source2 event records.

diff_source1_div_split_factor:
Difference between source1 implied vs explicit dividend/split factor.

diff_source2_div_split_factor:
Difference between source2 implied vs explicit dividend/split factor.

source1_return:
Final source1 adjusted return.

source2_return:
Final source2 adjusted return.

diff_return:
IMPORTANT SIGN CONVENTION:

diff_return = source1_return - source2_return

Therefore:
- positive diff_return => source1 return is higher
- negative diff_return => source1 return is lower

SPLIT RECONCILIATION RULE
==================================================

If:
- source1_div_split or source2_div_split contains sp:<split_factor>

Then:
expected_return_impact = split_factor - 1.0

Example:
sp:1.136 => expected_return_impact = +13.6%

Do NOT confuse:
- event return impact
with:
- backward price adjustment factor

For sp:1.136:
- event return impact = +13.6%
- backward price factor = 1 / 1.136
- backward price effect ≈ -11.97%

audit_returns() uses the EVENT RETURN convention.

When a split exists, compare:
- expected_return_impact
- diff_return
- source1_div_split_factor_explicit - 1.0
- source2_div_split_factor_explicit - 1.0
- implied dividend/split factor fields minus 1.0

If:
- source2 has the split
- source1 does not
- source2 dividend/split factor impact explains diff_return

Then:
likely_correct_source should usually be SOURCE2.

If:
- source1 has the split
- source2 does not
- source1 dividend/split factor impact explains diff_return

Then:
likely_correct_source should usually be SOURCE1.

==================================================
SPINOFF RECONCILIATION RULE
==================================================

Use SPINOFF when shareholders receive shares of a separated company or merger
partner through a spin-off, separation, or Reverse Morris Trust transaction.

If a data source event marker explains the return difference, use that marker as the
expected_return_impact.

If no marker exists but distributed-share value can be estimated,
expected_return_impact may approximate:

distributed value / prior close

Do NOT classify a spin-off as MERGER solely because the separated business
immediately combines with another company.

==================================================
CASH DISTRIBUTION RULE
==================================================

For:
ca:<cash_amount>
cd:<cash_amount>
sc:<cash_amount>

Approximate:
expected_return_impact = cash_amount / prior_close

Compare:
- explicit dividend/split factor impact, calculated as factor - 1.0
- implied dividend/split factor impact, calculated as factor - 1.0
- diff_return

Use the data source whose dividend/split factor impact reconciles correctly.

PRICING_METHOD RULE
==================================================

PRICING_METHOD may ONLY be used if ALL apply:

- no corporate action identified
- no material catalyst identified
- no event-return reconciliation exists
- discrepancy is economically consistent with pricing normalization

The evidence_summary MUST explicitly explain:

For PRICING_METHOD close-reversal rows where the input row evidence supports
SOURCE1 or SOURCE2 as the more reliable close series:
- expected_return_impact MUST be 0.0
- research_confidence MUST be MEDIUM

Interpretation:
- expected_return_impact is 0.0 because no corporate action, cash distribution,
  or company news explains an economic event-return adjustment.
- MEDIUM confidence means the row is actionable enough to prefer one data source's
  close series, but the conclusion is based on pricing-method reconciliation
  rather than direct data source documentation.

Example:
- A two-day close reversal has no dividend, split, spin-off, or news catalyst.
- source2 prices align with independent historical-price evidence.
- Use event_detected = NO, event_bucket = PRICING_METHOD,
  expected_return_impact = 0.0, likely_correct_source = SOURCE2,
  research_confidence = MEDIUM.



==================================================
NO ECONOMIC DIFFERENCE RULE
==================================================

Before assigning:
- PRICING_METHOD
- SOURCE1
- SOURCE2

the model MUST first determine whether source1 and source2 are economically equivalent.

A row is ECONOMICALLY EQUIVALENT if ALL apply:

- abs(source1_return - source2_return) < 0.000001
- abs(source1_adj_close - source2_adj_close) < 0.000001
- abs(source1_close - source2_close) < 0.000001
- no material event-return discrepancy exists
- no real-world event explains a data source difference

If ECONOMICALLY EQUIVALENT:

- likely_correct_source MUST be BOTH
- research_confidence should usually be LOW
- event_detected should usually be NO
- event_bucket should usually be UNKNOWN

The model MUST NOT:
- invent pricing-method explanations
- invent normalization differences
- imply data source disagreement
- imply one data source is more correct

The evidence_summary should explicitly state that:
- source1 and source2 are economically identical
- no meaningful reconciliation issue exists
- the row appears to be a non-actionable audit artifact or benign review trigger

==================================================
PRICING_METHOD RESTRICTION
==================================================

PRICING_METHOD may ONLY be used if:
- source1 and source2 materially differ economically
AND
- no real-world event explains the difference
AND
- the difference plausibly arises from adjusted-price methodology differences

PRICING_METHOD must NEVER be used when:
- prices are identical
- adjusted closes are identical
- returns are identical
- event-return math is identical


==================================================
LIKELY_CORRECT_SOURCE RULES
==================================================

Use SOURCE1 when:
- source1 reconciles to the real-world event and source2 does not
- source2 event-return math fails
- external evidence supports source1 treatment

Use SOURCE2 when:
- source2 reconciles to the real-world event and source1 does not
- source1 is missing an event adjustment
- source1 event-return math fails

Use BOTH when:
- source1 and source2 are economically equivalent
- differences are immaterial
- both treatments are defensible

Use NEITHER when:
- neither reconciles to the confirmed event

Use UNCERTAIN only when:
- the evidence truly does not support a data-source-specific conclusion

Do NOT use UNCERTAIN merely because direct data source documentation is unavailable.

When evidence is mixed, apply this tie-breaker order:

1. Prefer the data source whose event-return math reconciles to the confirmed event.
2. If both reconcile and differences are immaterial, use BOTH.
3. If neither reconciles to a confirmed event, use NEITHER.
4. Use UNCERTAIN only when the event itself or data source treatment cannot be determined.
