PRICE / ADJUSTED CLOSE FIELDS
--------------------------------------------------

ms_close:
Massive unadjusted close.

yf_close:
yFinance unadjusted close.

ms_adj_factor:
Massive cumulative adjustment factor.

yf_adj_factor:
yFinance implied adjustment factor:
yf_adj_close / yf_close

ms_adj_close:
Massive adjusted close:
ms_close * ms_adj_factor

yf_adj_close:
yFinance adjusted close.

--------------------------------------------------
EVENT MARKER FIELDS
--------------------------------------------------

ms_div_split:
Massive event marker string.

yf_div_split:
yFinance event marker string.

Split format:
sp:<split_factor>

Example:
sp:1.136

Cash distribution format:
ca:<cash_amount>

Example:
ca:0.82

Massive cash marker formats:
cd:<cash_amount> = Massive regular cash dividend.
sc:<cash_amount> = Massive special cash dividend.
ca:<cash_amount> = generic cash action/distribution marker when no regular/special distinction is available.

yFinance cash marker format:
ca:<cash_amount> = yFinance generic cash dividend/distribution marker.

For economic event matching, cd:<amount>, sc:<amount>, and ca:<amount> are all cash distribution markers. Do not treat cd/sc versus ca as an event-source mismatch by itself when the cash amount and date reconcile.

However, sc:<amount> is research-relevant. Special cash dividends more often create vendor adjustment, denominator, event classification, or timing differences than ordinary regular dividends. When ms_div_split contains sc:<amount>, explicitly investigate whether the special dividend caused the return difference or adjustment treatment.

Multiple same-day events are space-separated.

has_div_split_mismatch:
true when Massive and yFinance event markers differ.

--------------------------------------------------
RETURN FIELDS
--------------------------------------------------

ms_return_price:
Massive raw price return from unadjusted closes.

yf_return_price:
yFinance raw price return from unadjusted closes.

ms_div_split_factor_implied:
Massive implied dividend/split factor inferred from adjusted and raw price returns:
(1 + ms_return) / (1 + ms_return_price)

ms_div_split_factor_explicit:
Massive explicit dividend/split factor derived from Massive event records.

yf_div_split_factor_implied:
yFinance implied dividend/split factor inferred from adjusted and raw price returns:
(1 + yf_return) / (1 + yf_return_price)

yf_div_split_factor_explicit:
yFinance explicit dividend/split factor derived from yFinance event records.

diff_ms_div_split_factor:
Difference between Massive implied vs explicit dividend/split factor.

diff_yf_div_split_factor:
Difference between yFinance implied vs explicit dividend/split factor.

ms_return:
Final Massive adjusted return.

yf_return:
Final yFinance adjusted return.

diff_return:
IMPORTANT SIGN CONVENTION:

diff_return = ms_return - yf_return

Therefore:
- positive diff_return => Massive return is higher
- negative diff_return => Massive return is lower

SPLIT RECONCILIATION RULE
==================================================

If:
- ms_div_split or yf_div_split contains sp:<split_factor>

Then:
expected_return_impact = split_factor - 1.0

Example:
sp:1.136 => expected_return_impact = +13.6%

Do NOT confuse:
- event return impact
with:
- backward price adjustment factor

For sp:1.136:
- event return impact = +13.6%
- backward price factor = 1 / 1.136
- backward price effect ≈ -11.97%

audit_returns() uses the EVENT RETURN convention.

When a split exists, compare:
- expected_return_impact
- diff_return
- ms_div_split_factor_explicit - 1.0
- yf_div_split_factor_explicit - 1.0
- implied dividend/split factor fields minus 1.0

If:
- yFinance has the split
- Massive does not
- yFinance dividend/split factor impact explains diff_return

Then:
likely_correct_source should usually be YFINANCE.

If:
- Massive has the split
- yFinance does not
- Massive dividend/split factor impact explains diff_return

Then:
likely_correct_source should usually be MASSIVE.

==================================================
SPINOFF RECONCILIATION RULE
==================================================

Use SPINOFF when shareholders receive shares of a separated company or merger
partner through a spin-off, separation, or Reverse Morris Trust transaction.

If a vendor event marker explains the return difference, use that marker as the
expected_return_impact.

If no marker exists but distributed-share value can be estimated,
expected_return_impact may approximate:

distributed value / prior close

Do NOT classify a spin-off as MERGER solely because the separated business
immediately combines with another company.

CASH DISTRIBUTION RULE
==================================================

expected_return_impact = cash_amount / prior_close

Compare:
- explicit dividend/split factor impact, calculated as factor - 1.0
- implied dividend/split factor impact, calculated as factor - 1.0
- diff_return

Use the vendor whose dividend/split factor impact reconciles correctly.

NO ECONOMIC DIFFERENCE RULE
==================================================

Before assigning:

- MASSIVE
- YFINANCE

the model MUST first determine whether Massive and yFinance are economically equivalent.

A row is ECONOMICALLY EQUIVALENT if ALL apply:

- abs(ms_return - yf_return) < 0.000001
- abs(ms_adj_close - yf_adj_close) < 0.000001
- abs(ms_close - yf_close) < 0.000001
- no material event-return discrepancy exists
- no real-world event explains a vendor difference

If ECONOMICALLY EQUIVALENT:

- likely_correct_source MUST be BOTH
- research_confidence should usually be LOW
- event_detected should usually be NO
- event_bucket should usually be UNKNOWN

The model MUST NOT:
- invent pricing-method explanations
- invent normalization differences
- imply vendor disagreement
- imply one vendor is more correct

The evidence_summary should explicitly state that:
- Massive and yFinance are economically identical
- no meaningful reconciliation issue exists
- the row appears to be a non-actionable audit artifact or benign review trigger

==================================================
PRICING_METHOD RESTRICTION
==================================================

PRICING_METHOD may ONLY be used if:
- Massive and yFinance materially differ economically
AND
- no real-world event explains the difference
AND
- the difference plausibly arises from adjusted-price methodology differences

PRICING_METHOD must NEVER be used when:
- prices are identical
- adjusted closes are identical
- returns are identical
- event-return math is identical


==================================================
LIKELY_CORRECT_SOURCE RULES
==================================================

Use MASSIVE when:
- Massive reconciles to the real-world event and yFinance does not
- yFinance event-return math fails
- external evidence supports Massive treatment

Use YFINANCE when:
- yFinance reconciles to the real-world event and Massive does not
- Massive is missing an event adjustment
- Massive event-return math fails

Use BOTH when:
- Massive and yFinance are economically equivalent
- differences are immaterial
- both treatments are defensible

Use NEITHER when:
- neither reconciles to the confirmed event

Use UNCERTAIN only when:
- the evidence truly does not support a vendor-specific conclusion

Do NOT use UNCERTAIN merely because direct vendor documentation is unavailable.

When evidence is mixed, apply this tie-breaker order:

1. Prefer the vendor whose event-return math reconciles to the confirmed event.
2. If both reconcile and differences are immaterial, use BOTH.
3. If neither reconciles to a confirmed event, use NEITHER.
4. Use UNCERTAIN only when the event itself or vendor treatment cannot be determined.
